# PM Guide: GitHub in Product Management Language

If you are new to GitHub, use this page as your translation guide.

| GitHub Concept | PM Equivalent | Explanation |
|---------------|---------------|-------------|
| Issue | Feature / User Story | A single product request or problem to solve. |
| Pull Request | Feature Approval / Implementation Proposal | A proposed change for review before release. |
| Merge | Feature Released / Accepted | The proposal is approved and becomes part of the product. |
| Branch | Workstream / Initiative in progress | A focused lane of work for a specific improvement. |
| Label | Feature classification (priority, type, area) | Tags that help sort and prioritize work quickly. |
| Milestone | Release / Quarter | A time box (for example Q3) for planned delivery. |
| Project Board | Roadmap execution view | A visual board showing what is planned, in progress, or done. |
| Comment thread | Product discussion log | Decisions, trade-offs, and feedback in one place. |
| Assignee | Directly responsible owner | The person driving a feature forward. |
| Repository | Product workspace | The home for roadmap, documentation, and delivery work. |

## How to use this guide

When you see a GitHub term, map it to the PM equivalent above.
You do not need to know code to use this system effectively.
